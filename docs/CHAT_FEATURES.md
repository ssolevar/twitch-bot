# Функции чата

Русские и английские названия команд работают одинаково. Регистр не важен.

## FACEIT Elo

Добавьте server-side ключ FACEIT Developer API в `FACEIT_API_KEY` в `.env`. По умолчанию используется игра `cs2`; её можно сменить через `FACEIT_GAME_ID`. Игрок по умолчанию задаётся модератором командой `!setuser <ник>` и сохраняется в игнорируемом Git файле `data/faceit-user.json`; можно также задать начальное значение через `FACEIT_DEFAULT_NICKNAME`. Команда `!elo`, а также aliases `!эло` и `!удщ`, показывает Elo этого игрока. `!elo <ник>` разово показывает Elo указанного игрока и не меняет игрока по умолчанию. Для отсутствующего ключа бот остаётся запущенным; команда сообщает, что интеграция не настроена.

## Свои команды

Модератор или владелец канала может добавить, изменить и удалить ответ:

```text
!добком !тг https://t.me/ssolevar
!newcmd !казик Крутим колесо!
!измком !тг Новая ссылка
!удалком !тг
```

Для добавления также работают `!addcom`, `!дк`, `!lr` и `!эдком`; для изменения — `!editcmd`; для удаления — `!delcmd`, `!del`, `!delcom` и `!делит`. `!oncmd <команда>` и `!offcmd <команда>` включают и выключают команду.

Пример команды для повторного объявления: `!newcmd !анонс Подписывайтесь на Telegram: https://t.me/ssolevar`. Модератор может вызвать `!анонс 5`; число повторов ограничивается `MAX_COMMAND_REPEAT`.

Зритель получает один ответ. Модератор может повторить его, например `!тг 5`. Предел задаёт `MAX_COMMAND_REPEAT` (по умолчанию 10); сообщения отправляются с паузой `COMMAND_REPEAT_DELAY_MS` (по умолчанию 700 мс). `!тг -5`, `!тг 0`, `!тг abc` и `!тг 5.5` дают один ответ. Ответы команд, таймеров, напоминаний, автоответов, EventSub и прогнозов идут через общую очередь максимум на 100 активных и ожидающих сообщений.

Настройки команды:

```text
!добалиас !тг !telegram
!удалалиас !telegram
!алиасы !тг
!права !тг subscriber
!добответ !тг Другой текст
!ответы !тг
!удалответ !тг 2
!кд !тг 10
!юзеркд !тг 30
!выклком !тг
!вклком !тг
!кастомки
```

`!кд` задаёт общую паузу в секундах, `!юзеркд` — паузу для каждого пользователя. Ноль отключает паузу. Правило действует и для модератора. Из нескольких ответов бот случайно выбирает один. Отключённая команда остаётся в файле со всеми настройками, но не отвечает.

Права: `everyone`, `subscriber`, `vip`, `moderator`, `broadcaster`. VIP и подписчик проверяются независимо: VIP без подписки не проходит `subscriber`, подписчик без VIP не проходит `vip`. Модератор проходит оба уровня; владелец канала — все. `!кастомки` показывает только включённые команды, доступные зрителю.

В тексте ответа работают `{user}`, `{channel}` и `{uptime}`. Это подстановка текста, без выполнения кода. Если значение недоступно, бот подставляет `—`.

Новый формат `data/commands.json`:

```json
{
  "!тг": {
    "responses": ["https://t.me/ssolevar"],
    "aliases": ["!telegram"],
    "permission": "everyone",
    "enabled": true,
    "globalCooldown": 0,
    "userCooldown": 5
  }
}
```

Старые записи вида `"!тг": "текст"` загружаются без ручной правки. При следующем изменении команды файл сохраняется в новом формате.

Просмотр и перенос настроек:

```text
!инфоком !тг
!копком !тг !телеграм
!экспортком
!импортком
!импортком заменить
```

`!инфоком` показывает права, состояние, cooldown, алиасы и все варианты ответа. Копия получает настройки и ответы, но не алиасы: их имена должны оставаться уникальными. `!экспортком` сохраняет `commands.export.json` рядом с рабочим `commands.json`. Для импорта положите JSON в `commands.import.json` в той же папке. Обычный импорт добавляет команды и не перезаписывает существующие; `!импортком заменить` заменяет весь набор после проверки файла. Формат обоих файлов совпадает с примером выше. При конфликте имён или повреждённом JSON текущие команды остаются без изменений. Эти операции доступны модератору и владельцу канала.

## Таймеры и автоответы

```text
!добтаймер 15 Подписывайтесь на Telegram: https://t.me/ssolevar
!таймеры
!удалтаймер 1
!вклтаймер 1
!выклтаймер 1

!добавто telegram https://t.me/ssolevar
!автоответы
!удавто telegram
!вклавто telegram
!выклавто telegram
```

Таймеры проверяют активность чата за свой интервал. Если сообщений меньше `TIMER_MIN_CHAT_MESSAGES` (по умолчанию 5), отправка пропускается. Интервал — от 1 до 1440 минут, максимум 50 таймеров. После перезапуска сохраняются текст, интервал и состояние; счёт сообщений начинается заново.

Автоответ ищет ключевое слово в сообщении без учёта регистра. Команды с `!` и сообщения самого бота не запускают автоответ. Пауза для каждого ключевого слова задаётся `AUTO_REPLY_COOLDOWN_SECONDS` (по умолчанию 30). Настраивать таймеры и автоответы могут модераторы и владелец канала.

## Активный чат и напоминания

```text
!рандомчат
!рандомчат 3
!напомни 10 Время сделать перерыв
!напоминания
!удалнапоминание 1
```

`!рандомчат` выбирает до пяти разных участников, писавших за последние `ACTIVE_CHATTER_WINDOW_MINUTES` (по умолчанию 15). Бот и владелец канала в выбор не входят. Список хранится только в памяти.

Напоминания сохраняются с временем отправки. Можно поставить до 50 напоминаний на срок от 1 до 1440 минут. После перезапуска будущие напоминания восстанавливаются, просроченные пропускаются. Эти команды доступны модераторам и владельцу канала.

## Информация о канале и EventSub

`!title` / `!название` и `!game` / `!игра` получают название и категорию через Twitch Helix. Ответ кэшируется на `STREAM_INFO_CACHE_SECONDS` (по умолчанию 30). Данные доступны и для канала вне эфира.

Модератор или владелец может управлять стримом и режимами чата:

```text
!сменназвание Вечерний стрим
!сменкатегорию Just Chatting
!слоу 10
!слоу выкл
!фолловеры 30
!фолловеры выкл
!эмоуты вкл
!эмоуты выкл
!очиститьчат
```

Для смены названия и категории токен бота должен принадлежать владельцу канала и иметь `channel:manage:broadcast`. Категория ищется по точному названию Twitch. Название — до 140 символов. Slow mode принимает 3–120 секунд, followers-only — 0–129600 минут. Для этих режимов нужен `moderator:manage:chat_settings`, а для очистки чата — `moderator:manage:chat_messages`. Аккаунт бота должен иметь право модератора или владельца. При ошибке Twitch команда возвращает короткий ответ, подробность остаётся в локальном журнале. [Требования Twitch API](https://dev.twitch.tv/docs/api/reference).

EventSub может отправлять сообщения на follow, sub, raid, gift subs, resub, cheer/Bits, обновление названия/категории и начало/конец эфира. Включите `ENABLE_EVENTSUB=true`, затем настройте флаги и шаблоны в `.env`. Новые типы (`EVENT_GIFT_MESSAGE`, `EVENT_RESUB_MESSAGE`, `EVENT_CHEER_MESSAGE`, `EVENT_UPDATE_MESSAGE`, `EVENT_ONLINE_MESSAGE`, `EVENT_OFFLINE_MESSAGE`) по умолчанию выключены. В шаблонах работают `{user}`, `{channel}`, `{viewers}`, `{uptime}`, `{count}`, `{bits}`, `{months}`, `{duration}`, `{title}`, `{category}` / `{game}` и `{language}`. Это только реакция на новые события, без подсчёта статистики. Если WebSocket оборвался, бот подключается снова; при смене адреса по `reconnect_url` Twitch переносит прежние подписки.

Follow требует `moderator:read:followers` и роль модератора у аккаунта бота; sub, gift subs и resub — `channel:read:subscriptions` и токен владельца канала; cheer — `bits:read` и токен владельца. Raid, channel update и stream online/offline не требуют дополнительного scope. Если нужного scope нет, соответствующий тип события пропускается. Когда gift event подписан успешно, бот не дублирует сообщение для каждого подаренного sub. Подробнее: [типы EventSub](https://dev.twitch.tv/docs/eventsub/eventsub-subscription-types/) и [WebSocket](https://dev.twitch.tv/docs/eventsub/handling-websocket-events).

## Shoutout и клипы

Модератор или владелец канала может вызвать `!so <ник Twitch>` для shoutout и `!клип` для создания клипа текущего эфира. Для `!so` токен аккаунта бота должен иметь scope `moderator:manage:shoutouts`, а сам бот — быть модератором или владельцем канала. Twitch ограничивает shoutout: не чаще раза в две минуты и не чаще раза в час одному каналу. Для `!клип` нужен scope `clips:edit`; канал должен быть в эфире, а в Creator Dashboard должны быть разрешены клипы. Ссылка отправляется, когда Twitch обработает клип. Twitch описывает создание как асинхронное и просит считать его неудачным, если клип не появился через 15 секунд; в этом случае бот сообщает ID для проверки.

## Закрепы

`!добпин` добавляет сообщение в очередь. Также работает `!добавпин`:

```text
!добпин Telegram: https://t.me/ssolevar
!пины
!следпин
```

Бот отвечает номером нового элемента. `!следпин` удаляет его из очереди после успешного ответа Twitch. Если Twitch вернул ошибку, сообщение остаётся. Удалить элемент вручную можно через `!удалпин <номер>`, очистить очередь — через `!очиститьпины`.

Срок можно задать отдельно для каждого элемента: `!добпин 300 Telegram: https://t.me/ssolevar` закрепит на 300 секунд, `!добпин 0 Текст` — до конца эфира. Допустимы `0` или `30–1800` секунд. Если срок не указан, используется `PIN_DURATION_SECONDS`. Срок хранится вместе с элементом очереди и действует как при `!следпин`, так и при автоматической ротации. Старые файлы очереди со строками мигрируют при следующем сохранении; срок для них берётся из общей настройки.

Для часто используемых текстов есть пресеты:

```text
!добпинпресет тг Telegram: https://t.me/ssolevar
!пин тг
!пинпресеты
!удалпинпресет тг
!откреп
```

Если пресета с таким именем нет, `!пин` закрепляет введённый текст. Одно слово тоже считается текстом. `!пин 300 Привет` закрепляет текст на 300 секунд. Для закрепления существующего сообщения ответьте на него командой `!закреп` или `!pin`; число секунд можно передать после команды. Без ответа бот отправит и закрепит текст из `PIN_MESSAGE` в `.env`. Текущая длительность задаётся `PIN_DURATION_SECONDS` (по умолчанию 600 секунд); `0` означает до конца стрима, а `30–1800` задаёт число секунд. Эти настройки применяются и к `!следпин`. В канале может быть только один активный закреп от модератора: новый заменяет прежний.

Автоматическая ротация выключена по умолчанию. Для неё задайте `PIN_QUEUE_AUTO_ROTATE=true` и `PIN_QUEUE_INTERVAL_SECONDS=600`. Сообщения остаются в очереди в том же порядке; текущая позиция записывается отдельно в `data/pin-queue.json` и сохраняется после перезапуска.

## Опросы

Пресеты опросов лежат в `data/polls.json` или `data/<profile>/polls.json`. Если файла нет, бот читает общий `data/polls.example.json`.

```text
!опрос continue
!опросы
```

Опросы запускают модераторы и владелец канала. Для Twitch API токен должен принадлежать владельцу канала и иметь scope `channel:manage:polls`. Без этого бот продолжает работать, а команды опросов отвечают, что они отключены. Это обычные Twitch Polls, без Channel Points.

Имя пресета — от 1 до 32 символов (`a-z`, цифры, `_` или `-`). Заголовок — до 60 символов; вариантов ответа должно быть от 2 до 5, каждый до 25 символов. Длительность — от 15 до 1800 секунд.

## Локальные прогнозы

Прогнозы работают через сообщения в чате и не используют Twitch Predictions или Channel Points. Пресет создаёт модератор или владелец канала:

```text
!добпрог !винлуз 1 2 Вин/Луз 5
!добпрог !карта 1 2 Мираж/Инферно 0.30
```

Аргументы после команды пресета — два варианта голоса, название и время. Время задаётся как `минуты.секунды`: `5` означает 5 минут, `0.30` — 30 секунд, `1.30` — 1 минуту 30 секунд. Часть секунд должна быть от `00` до `59`, поэтому `1.99` не принимается.

Если название содержит `/`, его части становятся подписями вариантов. Для `Вин/Луз` бот показывает `1 — Вин` и `2 — Луз`. Запуск выполняется сохранённой командой:

```text
!винлуз
```

Пока прогноз активен, зрители пишут `1` или `2`. Каждый пользователь учитывается один раз; новый вариант переносит его голос. Сообщения самого бота не считаются, и бот не отвечает на каждый голос. Одновременно может идти только один прогноз. После истечения времени результат публикуется автоматически.

Управление пресетами и текущим прогнозом:

```text
!добпрог <команда> <вариант1> <вариант2> <название> <время>
!измпрог <команда> <вариант1> <вариант2> <название> <время>
!удалпрог <команда>
!проги
!прог
!закрытьпрог
!отменапрог
```

`!проги` показывает сохранённые команды, `!прог` — варианты и оставшееся время. `!закрытьпрог` сразу завершает голосование и публикует результат, а `!отменапрог` останавливает его без результата. Создавать, изменять, удалять и запускать пресеты, а также закрывать и отменять прогноз, могут модераторы и владелец канала. Просматривать список и текущий прогноз, а также голосовать могут все пользователи.

Имя команды пресета должно быть свободно: оно не может совпадать с системной командой, alias, своей командой или другим прогнозом. Пресеты хранятся в `data/predictions.json` или `data/<profile>/predictions.json`. Активный прогноз, таймер и голоса находятся только в памяти; после перезапуска бота прогноз считается отменённым.

## Файлы

Настройки хранятся в JSON-файлах внутри `data/` или `data/<profile>/`: `commands.json`, `timers.json`, `auto-replies.json`, `reminders.json`, `pin-queue.json`, `pins.json`, `polls.json` и `predictions.json`. Там же создаются файлы импорта/экспорта команд и, при включённом OAuth refresh, `oauth-tokens.json`. Git игнорирует рабочие файлы. В репозитории есть соответствующие `*.example.json`.

Если JSON-файл отсутствует, бот использует пустой список или пример. Если файл повреждён, бот пишет ошибку в журнал и не перезаписывает его. Отключается только функция, которой нужен этот файл; для пресетов закрепов и опросов бот может взять пример. Запись новых настроек выполняется через временный файл с последующей заменой.
